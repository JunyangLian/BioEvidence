# BioEvidence 失败案例分类（失败案例库）

**目的**：把项目里已发生、已登记的代表性失败组织成可检索的案例库——用于说明
"这个项目如何发现、归类和对待失败"，**不是**总体发生率估计。
**数据纪律**：每个案例的样本字段、原始输出与出处由脚本从冻结产物自动生成于
[`FAILURE_CASES.auto.md`](FAILURE_CASES.auto.md)（逐字引用）；本文件只做归类与分析。
**标签纪律**：答错 ≠ 没用证据；无 RESULTS ≠ 证据不足；摘录可回溯 ≠ 语义支持；
未经独立人工复核的判断均标注（工具辅助盲评 / AI 辅助评审）。

## 按类要点

### 目标构造风险（F03 / F04）
v2 代码级核查定位的两种训练目标构造风险——**不是自动判定为错误，而是提示需要
结合实际支持性判断来评估的风险**：
- F03：43.57% 的 yes 样本证据里没有结果段。这是目标构造的风险信号（模型可能学到
  "没有结果段也可以回答"），但具体某条样本是否确实可回答，需逐条人工判断。
- F04：36.55% 的 Reason 目标是整段逐字而非一句话。这是目标构造的风险信号（模型可能
  学到"引用整段"），但不自动等于"目标错误"——有些 chunk 确实只含一句结论。
- 两者对实际行为的影响已由 C-1 受控对照检验（负结果：弃答崩坏）。

### 引用问题（F02 / F08 / F10）
三种不同形态：引用完全不对题（F02：跨文献引用，E1 为 HRQOL 文献而问题关于 leptin——
主要归入引用问题，与监督目标的 answerable 代理定义有关联但非直接因果）、
引用忠实度不足（F08：把整体顶点结论推广到区域顶点）、引用主题无关（F10：检索带入）。
**引用合法（编号在范围内）不等于引用忠实，更不等于语义支持**——这是项目把引用检查
分为"机械合法性"与"语义支持"两层的原因。
### 弃答问题（F06 / F09 / F11）
三种不同形态：**正确弃答但契约违规**（F06：v3 在 V16 上）、**过度保守弃答**（F09：dev26 上
两流程都该答而不答）、**弃答崩坏**（F11：v2 微调负结果，弃答率 94.7%）。
三者说明"弃答行为"不是一个单一指标能概括的——校准、契约与真值都要分开看。

### 格式与契约（F01 / F06 / F13）
F01（重复循环）、F13（占位符复述）是格式层失败，均已通过提示/预算修复并冻结；
F06 是契约层偏差（弃答引用非空），**未修复、如实登记**。解析成功（30/30）与完整契约通过
（29/30）因此分开报告。

### 工程运行可靠性（F12）
VRAM 挂死是**基础设施/运行可靠性**问题，**不是**回答稳定性问题。回答稳定性的证据来自
v2 阶段 B 的证据换序对照（B0–B3：同题换序后 52.35%/45.70%/43.08% 的标签发生变化）。
两者属不同维度，不得混称。
